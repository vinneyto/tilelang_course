# Первая редукция по строкам

Редукция отличается от elementwise-ядра: несколько значений должны сойтись в
один результат. Сначала реализуем переносимый baseline через scalar accumulator
и `T.Serial`. Он намеренно использует один thread на строку и будет медленным,
но одинаково выражается на CUDA и Metal. Это полезная точка отсчёта: сначала
корректная формула, затем параллельная редукция и benchmark.

## Задание

Реализуйте `build_row_sum(M, N=256)`. Один block обрабатывает одну строку:

1. `with T.Kernel(M, threads=1) as row`;
2. `acc = T.alloc_var("float32")` и обнуление accumulator;
3. цикл `for col in T.Serial(N)`;
4. `acc += X[row, col]`;
5. запись `Y[row] = acc`.

После прохождения курса сравните этот baseline с `T.reduce_sum` на вашем
backend. У параллельных reduction больше требований к ширине, layout и числу
threads, поэтому они вынесены за пределы гарантированного M4-маршрута.

## Новые конструкции TileLang

- `threads=1` задаёт один GPU-thread на блок. Это сознательно простой, а не
  быстрый вариант.
- `T.alloc_var("float32")` создаёт скалярную локальную переменную. В данной
  модели `acc` принадлежит одному thread, в отличие от `T.alloc_shared`, общий
  буфер которого видит весь блок.
- `T.Serial(N)` описывает последовательный цикл. Следующая итерация начинается
  после предыдущей; compiler не распределяет столбцы между threads.

Редукция требует начального значения. Если не выполнить `acc = 0.0`, первое
сложение использует неопределённое содержимое локальной переменной.

## Параллель с WebGPU

Один блок соответствует одной workgroup, но её размер здесь равен 1. Поэтому
`row` можно мысленно сопоставить с `workgroup_id.x`, а цикл по `col` — с обычным
WGSL `for`, выполняемым единственной invocation.

Это не типичная быстрая WebGPU-редукция. Обычно workgroup совместно загружает
строку в `var<workgroup>`, затем выполняет древовидное суммирование с barriers.
Baseline нужен, чтобы сначала отделить правильную формулу редукции от её
параллельной оптимизации.

## Как решить по шагам

1. Создайте JIT-фабрику и внутренний kernel с входом
   `X: T.Tensor((M, N), "float32")` и выходом
   `Y: T.Tensor((M,), "float32")`.
2. Запустите ровно `M` блоков: `with T.Kernel(M, threads=1) as row`. Каждый
   блок получает одну строку, поэтому дополнительный расчёт глобального
   индекса не нужен.
3. Внутри блока выделите `acc = T.alloc_var("float32")`.
4. Следующей строкой явно присвойте `acc = 0.0`.
5. Откройте `for col in T.Serial(N)` и на каждой итерации прибавляйте
   `X[row, col]` к `acc`.
6. Запишите `Y[row] = acc` только после завершения цикла, а не внутри него.
7. Верните kernel из фабрики.
8. Сравните порядок вычислений с `x.sum(dim=1)`: уменьшается размерность `N`,
   а размерность `M` остаётся в результате.

Перед запуском полезно проследить маленький пример `M=2`, `N=3`: будут два
независимых блока, каждый последовательно выполнит три сложения и одну запись.
