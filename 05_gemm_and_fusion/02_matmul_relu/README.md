# Fusion: GEMM + ReLU

Если после GEMM запустить отдельный ReLU, результат C сначала запишется в global
memory, а затем снова прочитается. Эпилог внутри того же ядра применяет ReLU к
`C_local` до store. Это классический operator fusion.

Важно различать две оптимизации:

- tiling переиспользует A/B и ускоряет основное вычисление;
- fusion убирает промежуточный global-memory round trip.

## Задание

Скопируйте рабочую структуру GEMM из предыдущего задания в
`build_matmul_relu`. После завершения K-loop, но до записи C, примените
`T.max(C_local[i, j], 0)` через `T.Parallel(block_M, block_N)`.

Сохраните Metal-совместимые параметры предыдущего задания: shared accumulator,
`num_stages=0`, тайлы `32 × 32 × 16` и `float32` output.

Не вызывайте отдельное PyTorch `relu` внутри решения.

## Новые конструкции и порядок операций

Новой функции TileLang здесь нет: упражнение показывает, где в dataflow
размещается эпилог. `T.Parallel(block_M, block_N)` обходит все элементы уже
готового `C_local`, а `T.max(C_local[i, j], 0.0)` меняет их до выгрузки.

Порядок принципиален:

```text
clear C_local → все K-шаги T.gemm → ReLU в C_local → T.copy в global C
```

Если применить ReLU внутри K-loop, отрицательная промежуточная сумма будет
обнулена слишком рано, а следующие K-тайлы уже не смогут восстановить
математически правильный результат.

## Параллель с WebGPU

В WGSL это был бы дополнительный `max(acc, 0.0)` перед записью каждой ячейки
аккумулятора в storage buffer. Отдельного compute pass и отдельного storage
buffer для результата GEMM не появляется.

`T.Parallel` здесь удобнее читать как логическое покрытие всех элементов
эпилога. Не следует предполагать, что тайл `32 × 32` требует 1024 физических
threads: kernel запускается со 128 threads, а compiler распределяет 1024
итерации между ними.

## Как решить по шагам

1. Сначала добейтесь прохождения предыдущего `tiled_matmul`; структура grid,
   shared-тайлов и K-loop здесь полностью та же.
2. Перенесите эту структуру в `build_matmul_relu`, сохранив формы и dtype всех
   трёх аргументов.
3. Убедитесь, что `T.clear(C_local)` стоит до `T.Pipelined`, а все вызовы
   `T.gemm` — внутри него.
4. Сразу после K-loop добавьте
   `for i, j in T.Parallel(block_M, block_N)`.
5. В теле цикла присвойте каждому элементу `C_local` максимум между текущим
   значением и нулём.
6. Только после ReLU выполните `T.copy(C_local, C[...])`.
7. Верните kernel и сравните с reference именно в таком порядке:
   `torch.relu(a.float() @ b.float())`.
8. Для самопроверки придумайте результат GEMM с отрицательными элементами:
   после эпилога они должны стать нулями, положительные — не измениться.
